# BUGS

Результат проверен автоматизированными тестами 2026-09-07T11:03:10+00:00.

## BUG-001: пользователь может удалить чужое объявление

- **Серьёзность:** Critical
- **Окружение:** `https://qa-internship.avito.com`
- **Предусловия:** зарегистрированы и авторизованы два уникальных пользователя A и B.
- **Шаги воспроизведения:**
  1. Создать объявление от имени A с sellerID пользователя A.
  2. Отправить DELETE `/api/2/item/{id}` с bearer-токеном пользователя B.
  3. Получить объявление с bearer-токеном владельца A.
- **Фактический результат:** DELETE возвращает HTTP 200, последующий GET владельца возвращает HTTP 404.
- **Ожидаемый результат:** Удаление отклоняется с HTTP 403/404; объявление остаётся доступно владельцу.

## BUG-002: нулевое значение счётчика статистики воспринимается как отсутствующее поле

- **Серьёзность:** Medium
- **Окружение:** `https://qa-internship.avito.com`
- **Предусловия:** пользователь зарегистрирован и авторизован.
- **Шаги воспроизведения:**
  1. Подготовить валидное объявление с положительной ценой и счётчиками.
  2. Поочерёдно передать 0 в likes, viewCount и contacts.
  3. Отправить POST `/api/1/item` с валидным bearer-токеном.
- **Фактический результат:** Для вариантов `likes-zero, view-count-zero, contacts-zero` сервис возвращает HTTP 400 и сообщает, что соответствующее поле обязательно.
- **Ожидаемый результат:** Значение 0 принимается как переданное неотрицательное значение счётчика.

## BUG-003: HTTP-статус ошибки statistic v2 не совпадает с полем status в JSON

- **Серьёзность:** Medium
- **Окружение:** `https://qa-internship.avito.com`
- **Предусловия:** пользователь зарегистрирован и авторизован.
- **Шаги воспроизведения:**
  1. Выполнить GET `/api/2/statistic/not-a-uuid` с валидным bearer-токеном.
  2. Сравнить HTTP-код ответа и поле `status` в JSON.
- **Фактический результат:** HTTP-ответ имеет код 404, но тело содержит `"status": "400"`.
- **Ожидаемый результат:** HTTP-код и поле `status` согласованы и описывают одну ошибку.
