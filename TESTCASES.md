# TESTCASES — API задания 2.1

## Общие предусловия

1. Доступен `https://qa-internship.avito.com`.
2. Установлены зависимости из `requirements.txt`.
3. Пользователи, пароли, названия объявлений и UUID создаются динамически.
4. Токен для защищённых ручек получается через `POST /api/1/autorize`.
5. Созданные объявления удаляются после тестов, если это возможно.

Применены классы эквивалентности, анализ граничных значений, таблицы решений для доступа,
переходы состояний, негативное тестирование и error guessing.

## Регистрация и авторизация

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| REG-01 | Уникальный пользователь | POST `/api/1/register` с уникальными данными | 201; integer `id`, исходный `username`, пароль отсутствует |
| REG-02 | Дубликат username | Повторить регистрацию | Первый ответ 201, второй 409 |
| REG-03 | Нет username | Передать только password | 400 |
| REG-04 | Нет password | Передать только username | 400 |
| REG-05 | Пустые credentials | Передать пустые строки | 400 |
| REG-06 | Повреждённый JSON | Передать незавершённый JSON | 400, не 500 |
| AUTH-01 | Валидная авторизация | Зарегистрироваться и вызвать `/autorize` | 200; непустой `accessToken`; `tokenType=Bearer` |
| AUTH-02 | Неверный пароль | Авторизация существующего пользователя | 401 |
| AUTH-03 | Неизвестный username | Авторизация случайного пользователя | 401 |
| AUTH-04 | Нет обязательного поля | Передать только username | 400 |
| AUTH-05 | Публичные POST-ручки | Register и autorize без Authorization | Отсутствие токена не вызывает 401 |

## Доступ и безопасность

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| SEC-01 | Защищённые ручки без токена | Вызвать create/get/list/stat v1/v2/delete | 401 |
| SEC-02 | Невалидный токен | Передать `Bearer invalid.jwt.token` | 401 |
| SEC-03 | Обход через X-UserId | Создать item без bearer с X-UserId | 401 |
| SEC-04 | Чужой sellerID | Токен A, sellerID B | 400/401/403; item не создаётся |
| SEC-05 | X-UserId не подменяет bearer | Токен A, sellerID B, X-UserId B | Запрос отклонён |
| SEC-06 | Удаление чужого item | B удаляет item пользователя A | 403/404; item остаётся доступен A. `BUG-001` |

## E2E и нефункциональные проверки

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| E2E-01 | Полный жизненный цикл | register → authorize → create → get → stats → list → delete | Все переходы корректны; после delete 404 |
| NF-01 | Content-Type | Проверить успешный ответ | Содержит `application/json` |
| NF-02 | Время авторизации | Измерить запрос | Не более `MAX_RESPONSE_TIME_MS` |
| NF-03 | Неподдерживаемый метод | GET `/api/1/register` | 401/404/405; не 2xx и не 500 |
| NF-04 | SQL-подобный username | Передать строку и неверный пароль | Нет 500 и обхода авторизации |
| NF-05 | Отсутствие секретов | Запустить `check_no_secrets.py` | Нет JWT и динамических паролей |
| NF-06 | Воспроизводимость | Повторный запуск/иной порядок | Нет конфликтов и зависимости от общего стенда |
